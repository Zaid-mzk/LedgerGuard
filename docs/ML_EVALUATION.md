# ML methodology

`backend/scripts/generate_synthetic_transactions.py` uses NumPy with a fixed random seed to create a synthetic dataset with transaction amount, velocity, account age, time gap, receiver diversity, amount ratio, new-receiver indicator and hour. `synthetic_label` is an evaluation label and is not included in the model feature list.

`backend/scripts/train_risk_model.py` fits an Isolation Forest to normal rows from the training split, selects an anomaly-score threshold on validation data and reports precision, recall, F1 and confusion matrix on the held-out test split. Output is written to `backend/artifacts/model_evaluation.json`. The values must be generated by running the script; no result is prefilled here. They describe only the chosen synthetic generator and do not represent real fraud detection performance.

The API's current risk flags are produced by deterministic rules (`rules-v1`), not by the offline model. This separation keeps inference from changing transfers, balances or ledger entries.
